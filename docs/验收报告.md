约定：

- 每个断言消息都带 **方法 + 路径 + 期望值 + 实际响应**（如
  `POST /api/generate 期望 HTTP 200，实际 400；响应体：{...}`），失败可直接定位到接口。
- 错误响应对 `{"error":{"code","message"}}` 做**结构断言 + code 精确匹配**，不只看状态码。
- 页数一致性做三方对照：`/api/generate.pages` == 下载的 `deck.pptx` 实际页数 == `deck.html` 的 `.slide` 段落数。
- 临时 store 每次全新（`uuid` 子目录），不读取 `server/store` 里的历史数据。

## 5. 缺陷与遗留问题

### 缺陷 1（P2，非 T4 阻塞）：`deck.html` 没有套用风格档案的配色

> **状态：已在 T7 修复。** `html_deck.build()` 新增可选 `theme_obj`，服务端 `_build_html()` 传入
> `profile.apply()` 的 `Theme`（并先完成 F10 的 CSS 颜色/字体白名单）；网页版与 pptx 现在同色，
> 回归断言见 `tests/test_server.py::test_24`。以下为 T4 当时的复现记录，保留作历史依据。

T1 已在 `docs/API.md` §7.1 记录该内核签名缺口，本次端到端**实测复现并量化**：

- 接口：`POST /api/generate`（`profile_id` + `theme`），产物 `GET /files/<id>/deck.html`
- 期望：网页版与 pptx 一样使用档案配色（档案 `palette.accent = #1B3A6B`）
- 实际：`deck.pptx` 的文字/填充显式色为 `#1B3A6B`（档案生效），但 `deck.html` 的 CSS
  `--accent` 取自所选基础主题；选 `theme=editorial` 时为 `#1F3BFF`
- 根因：`server/jobs.py` 的 `_build_html()` 只把 `theme_key` 传给
  `kit/pptxkit/html_deck.py::build()`，而该函数只接受主题名、没有 `theme_obj` 参数
- 复现步骤（仓库根目录，离线）：把下面代码存成 `.tmp\repro_html_profile.py`，

  ```python
  import json, os, re, shutil, sys, threading, urllib.request
  sys.path.insert(0, "."); sys.path.insert(0, "kit")
  for k in ("PPT_LLM_BASE_URL", "PPT_LLM_API_KEY", "PPT_LLM_MODEL"):
      os.environ.pop(k, None)
  from server.app import create_server
  shutil.rmtree(".tmp/repro-store", ignore_errors=True)
  httpd, base = create_server("127.0.0.1", 0, ".tmp/repro-store")
  threading.Thread(target=httpd.serve_forever, daemon=True).start()

  def call(method, path, data=None, headers=None):
      request = urllib.request.Request(base + path, data=data, method=method,
                                       headers=headers or {})
      with urllib.request.urlopen(request, timeout=60) as response:
          return response.read()

  raw = open("tests/fixtures/case-academic.pptx", "rb").read()
  profile = json.loads(call("POST", "/api/profiles", raw,
                            {"X-Filename": "academic-defense.pptx"}))["profile"]
  deck = json.loads(call("POST", "/api/generate", json.dumps({
      "prompt": "复现", "profile_id": profile["id"], "pages": 6, "theme": "editorial",
  }, ensure_ascii=False).encode(), {"Content-Type": "application/json"}))
  html = call("GET", deck["files"]["html"]).decode("utf-8")
  print("档案 accent =", profile["palette"]["accent"])
  print("html  accent =", re.search(r"--accent:\s*(#[0-9A-Fa-f]{6})", html).group(1))
  httpd.shutdown(); httpd.server_close(); shutil.rmtree(".tmp/repro-store", ignore_errors=True)
  ```

  然后执行：

  ```powershell
  & "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" .tmp\repro_html_profile.py
  ```

  实测输出（本次验收已运行）：

  ```text
  档案 accent = #1B3A6B
  html  accent = #1F3BFF     # 来自 editorial 基础主题，不是案例配色
  ```

- 建议：由 T2 给 `html_deck.build()` 增加可选 `theme_obj`（与 `builder.build` 对齐），
  服务端 `_build_html()` 传入 `kitlink.apply_profile()` 的结果；属内核签名变更，需队长协调。
- 对 T4 的影响：不阻塞验收（T4 口径只要求 `deck.html` 可下载且非空），但「网页版也向案例靠拢」
  这一目标当前只完成了一半，建议在 T5 评审前修复。

### 观察 2（P3）：生成的 pptx 只把档案配色写在形状/文字显式颜色上

`deck.pptx` 的 `ppt/theme/theme1.xml` 仍是 python-pptx 默认主题（`accent1=4F81BD`），
档案配色体现在每个形状/文字的显式 RGB 上（实测首屏 run 颜色 `#1B3A6B / #14213D / #5C6B82`）。
观感与「可编辑」不受影响；但若用户在 PowerPoint 里改「主题色/变体」，幻灯片不会跟随。
属设计取舍，供 T5 评审判断是否需要同步改写 theme part。

### 观察 3（P3）：25 MB 上限基于 `Content-Length`，真发超限请求体会连接复位

服务端在读请求体之前就用 `Content-Length` 拦下并返回 413（符合契约），因此测试构造的是
「声明 26 MB、不实际发送 26 MB」的请求；实测真发 26 MB 时 Windows 会在服务端提前关闭连接时
复位套接字，客户端拿不到 413 响应（`ConnectionAbortedError 10053`）。这不是接口缺陷（拦截时机正确），
仅记录测试写法，避免后续同学误判。

### 观察 4（P3）：旧版 `.ppt`（OLE）无法离线解析

返回 400 `invalid_pptx` 并提示另存为 `.pptx`（`docs/API.md` §7.2 已记录），已在异常路径中覆盖。
