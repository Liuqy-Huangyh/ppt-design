## 3. 数据模型、内核签名与反馈规则

- **§4.1 档案**：`id/name/source/created_at/slide_size/palette/fonts/metrics/style/learn` 全部存在；颜色统一大写 `#RRGGBB`；样例 `out/academic-defense.pptx` 分析出 17 页、`slide_size=[13.33,7.5]`、`accent=#1B3A6B`、`title_pt=31.0`、`image_ratio=0.12`；`density∈[0.6,1.4]`、`title_scale∈[0.85,1.25]` 由 `learn` clamp 复现。
- **§4.2 meta**：`id/created_at/title/theme/profile_id/pages/files/outline_chars/llm_used` 齐全，`files` 为 `{"pptx":"deck.pptx","html":"deck.html"}`。
- **§6 内核签名**：`profile.analyze/save/load/list_all/apply/learn`、`outline.llm_available/build_outline`、`builder.build(..., theme_obj=...)` 均与契约一致；`profile.apply()` 返回 `themes.Theme`（frozen dataclass + `clone_with`），`title_size` 乘 `title_scale`。
- **§7 迭代规则**：`rating≥4 → density×1.03`、`=3` 不变（message「已记录评分，本次无需调整」）、`≤2 → density×0.90, title_scale×0.97`；`learn.rounds+1`；`history` 项为 `{at,rating,density,title_scale,notes}`；档案立即落盘、`feedback.jsonl` 追加。
- **降级行为**：`profile.analyze` 对损坏/空/缺文件返回默认档案不抛异常；服务端另用 OOXML 结构校验先拦截垃圾字节（`jobs._is_ooxml_pptx`），因此无效上传仍是 400 而非「默认档案入库」。`outline.build_outline` 的 LLM 失败自动降级到离线启发式，返回的 Markdown 能被 `markdown.parse` 解析。

## 4. 安全评审

### 4.1 通过项

| 检查 | 结果 |
|---|---|
| 上传大小 | `Content-Length > 25 MB` → 413 `payload_too_large`；`create_profile` 再按实际字节复查 |
| 扩展名 | 只收 `.pptx/.ppt`，其它 → 400 `invalid_filename`（前端也预检） |
| 文件名不参与路径 | 落盘固定 `cases/<新 id>/source.pptx`、`tmp/<uuid>.<ext>`；`..`/`/`/`\`/NUL 一律 400；percent-encoding 先还原再校验 |
| 下载 name 白名单 | 仅 `deck.pptx`/`deck.html`；`valid_id` 正则 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` |
| 路径穿越 | `/files/<id>/../../etc/passwd`、`..%2F`、`%2e%2e%2f`、`/api/../health`、`/../server/app.py` 全部 404 且无内容泄漏；静态目录用 `base in candidate.parents` 兜底 |
| 可执行注入 | 全仓无 `eval/exec/pickle/subprocess/os.system`；前端零 `innerHTML`（全部 `textContent`），`chip.style.backgroundColor` 仅接受 `^#[0-9A-Fa-f]{6}$`；`deck.html` 的标题/正文/备注经 `html.escape`，实测把 `# <script>alert(1)</script>` 写进 outline，产物里是 `&lt;script&gt;`，无原始脚本。当前不存在可达的可执行注入；F10 记录的是一条「修 F3 时会被激活」的潜在注入 |
| 500 不泄漏栈 | 异常只回 `internal`，traceback 仅打印到服务端日志 |

### 4.2 未通过：服务器任意本地图片读取（F1）

`POST /api/generate` 的 `outline` 允许 Markdown 图片语法。`kit/pptxkit/builder.py::_resolve()` 对**绝对路径**原样返回（不校验是否在 `base_dir` 内），`layouts.picture()` 直接 `add_picture`。实测：

```text
outline = "# 图片页\n- 要点\n\n![](C:/Windows/Web/Wallpaper/Spotlight/img14.jpg)\n"
→ 200，pages=1
→ 下载 deck.pptx 内 ppt/media/image1.jpg = 1,602,752 B（与源文件逐字节同大小）
→ deck.html 同时包含绝对路径 C:/Windows/Web/Wallpaper/Spotlight/img14.jpg
```

`..` 逃逸同理：`![](../../Windows/win.ini)` 被解析到工作区之外的 `C:\Users\91125\Windows\win.ini`（本次因该文件不存在而回退为 bullets），说明图片路径解析完全落在服务端文件系统上、可以走出工作区。契约第 5 节允许用户直接提交 outline，服务又支持绑定 `0.0.0.0`，且无鉴权 → 局域网内任意主机可借服务读出本机任意图片（截图、照片等）并下载。**这是 T5 验收口径「无任意文件读取」的直接违反**，必须修。

### 4.3 其他安全观察（不单独列为阻塞）

- 用户 outline 派生的页数无上限（F4，资源放大）。
- CORS 通配 `*` ＋ 无鉴权 ＋ 可绑 `0.0.0.0`（F7）。
- 压缩炸弹：25 MB 的 OOXML 若解压后极大，`profile.analyze` 会全量解析；未做解压体积/页数上限（与 F4 同类，建议一并加限制）。
- `ThreadingHTTPServer` 每请求一线程、无读超时，慢速连接可占线程（建议 `Handler.timeout` + 并发上限）。
- `html_deck` 把主题字体名直接插入 `<style>`（F10：已实测上传 pptx 可让档案字体带回 `</style><script>`；当前 html 不用档案字体所以不可达，修 F3 时必先处理）。

## 9. 观察与建议（不阻塞，供后续迭代）

1. **契约 §5 摘要措辞**：`GET /api/profiles` 的「不含 palette 以外的冗余」含糊；实际返回 `fonts/style/slides/learn`，前端也确实需要。建议契约改成明确字段清单。
2. **方法语义**：`GET /api/generate` 返回 404 而不是 405；`HEAD /api/health` 因未实现 `do_HEAD` 返回 501（`_send_bytes` 里已有 HEAD 分支，属未接线）。建议统一 405 或补 `do_HEAD`。
3. **LLM base URL 拼接不一致**：`server/jobs.py:331` 总是 `base + "/chat/completions"`；`kit/outline.py:_chat_endpoint` 会识别已带 `/chat/completions` 的写法。建议服务端复用同一规则（或文档明确 base 不得带路径）。
4. **`density` 的字数效果非单调**：`profile.learn` 降低 density 后，`outline._fit()` 因断点阈值（`outline.py:526-534`）可能返回**更长**的要点（实测 density 0.61 的要点比 0.79 长）。要点条数（`round(base*density)`）方向正确；建议给 `_fit` 增加「无人可断点时按字数硬截断」或至少不放大。
5. **0 页/空壳 pptx**：实测只含 `ppt/presentation.xml` 的空壳 zip 仍被接受为档案（`metrics.slides=0`，默认配色），生成也能正常用（200，5 页）。若想更严格，可在 `create_profile` 里要求 `slides>=1` 返回 400。
6. **压缩炸弹/慢连接**：25 MB 上传无解压体积上限；`ThreadingHTTPServer` 无读超时、无并发上限。建议与 F4 一起加资源上限（解压后总字节、页数、连接超时）。
7. **pptx 主题 part 未同步**：档案色只写显式 RGB，`theme1.xml` 仍为默认主题（T4 观察 2）；若希望用户在 PowerPoint 里改主题色能整体联动，需要额外改写 theme part——属产品取舍，建议在文档里写明。
8. **前端未暴露 `org`**：契约 §5 的 generate 接受 `org`，UI 没有输入框（不影响接口；如需「单位」展示可补一个字段）。
